# 分析与方案引擎

## 目标

针对当前咖啡、全部可用器材、水、配方、过程、感官和目标，独立形成可执行方案。唯一默认目标是优化当前下一杯；专业质量、目标匹配、表达覆盖、信息与体验增量、执行风险和咖啡消耗共同参与总体价值判断。过程与感官观察用于验证和更新判断，但验证不等于限制为单变量微调。

## 会话状态路由

每轮先判断消息属于：

1. 当前咖啡的新结果；
2. 当前咖啡的下一杯修改；
3. 对既有方案的解释、来源或格式追问；
4. 新咖啡或新对象；
5. 个人默认、库存或会话全局规则更新。

按照 `../personal-profile.md` 为每条信息分配作用域。新咖啡创建新的 `case_id`，只继承 `profile_global` 与仍然有效的 `session_global`。原咖啡的剩余量、目标、器材选择、参数、实验要求和感官结果继续留在原 `coffee_case`。

把历史冲煮参数视为对象证据。除非用户明确把它定义成默认或约束，历史中的温度、比例、滤杯、闷蒸和注水结构都只支持解释该杯结果。

解释型与来源型追问先核对原决定依据。依据仍成立时使用 `delta` 模式并保持配方状态；追问暴露身份错误、无依据假设、参数冲突、遗漏联动，或改变器材、参数、下一杯目标时，建立 `correction`，转回 `full` 模式并重新输出可独立执行的方案。

## 单次冲煮记录的证据粒度门

任何历史记录进入推理前先绑定唯一 `case_id + brew_id`，并拆成：

1. **完整配置事实**：咖啡与样品状态、滤杯、纸、水、粉量、研磨、温度、注水、扰动、时间与结束条件；
2. **过程观察**：实际流速、水位、堵塞、床面、温度或操作偏差；
3. **感官观察**：入口、中段、尾段、余韵、降温与用户评价；
4. **用户解释**：用户明确提出的原因判断；
5. **Skill 推断**：候选机制、替代解释、置信度与需要验证的条件。

为每条后续主张记录来源观察、主张范围、边界条件和迁移状态。单杯直接支持完整配置与结果的共现；同一咖啡后续可以把它作为对象级证据建立候选机制。某个单独参数的因果作用需要有意义的对照、独立过程证据或多个独立冲煮在相近边界下重复；否则保持为 `whole_configuration_observation` 或 `case_evidence`。

迁移到另一咖啡、样品状态、滤杯、滤纸、水或粉量时，先填写共享条件、变化边界、原记录能支持的窄结论和目标验证。重复粘贴、回顾或汇总同一 `brew_id` 不增加证据权重。多个记录形成模式前先去重并检查它们是否独立，以及共同点是否只是同一烘焙商、品种、处理或器材标签。

单次正面或负面结果不会生成“某滤杯总是适合/不适合”“某温度对用户总是过高”“某研磨刻度是稳定中心”等广域规则。用户明确声明个人默认或稳定偏好时，再按个人档案规则单独保存，并保留适用范围。

## 配方纠错的失效传播门

用户指出配方问题、质疑某项是否成立，或 Agent 自检发现前提错误时，建立 `correction` 并依次执行：

1. **定位纠正内容**：区分对象身份、库存/可用性、用户条件、事实、机制假设、器材适配、参数选择、算术/时间轴或纯表达错误；
2. **替换最小源事实**：只在正确的 `scope` 与 `applies_to` 中更新事实，保留原记录追溯；
3. **标记失效决定**：列出直接依赖该前提的路线、候选排序、器材—滤纸系统、粉量传播、比例、研磨、热、润湿、注水、水位、扰动、时间预算和结束条件；
4. **回到最后有效上游**：如果问题影响器材适配，重新运行完整候选池与路线选择；如果影响粉量、纸、研磨、温度或注水结构，从对应共同求解步骤重新运行全部下游关系；
5. **重新确认保留项**：参数只有在新前提下仍有对象依据、系统作用和协同一致性时进入 `revalidated_parameters`；其余进入 `changed_parameters`；
6. **交付完整方案**：显示“纠正的前提 / 失效的决定 / 重新确认 / 改变”，再给完整摘要表、时间轴、时间预算、逻辑与观察重点。

用户只点名一个问题代表发现了一个失效入口，不代表其他参数自动有效。纯错字、单位排版或不会改变任何事实、推断与参数关系的显示错误可以局部修正；执行前仍完成依赖审计，并简要说明系统未受影响的理由。

## 器材实体解析与来源隔离门

器材选择前必须完成以下门控；未完成时不能进入功能分组或配方设计：

1. **读取唯一私人主档**：当前决定依赖既有库存、简称、滤纸或默认值时，先读取当前消息、会话状态和唯一 `private-coffee-profile.md`；不得查找、合并或维护平行私人登记；优先级固定为当前消息 > 当前会话 > 唯一主档；
2. **检查客观缓存命中**：滤杯按品牌、完整型号、尺寸、材质、版本/联名和当前组件匹配；滤纸按完整产品线/SKU、形状、标称尺寸/型号和材质匹配。复用身份、尺寸、材质、主体几何、出口/阀门和全部已核实接口，并记录命中、缺失、冲突和需增量研究的字段；
3. **解析当前称呼**：从当前请求、会话状态、唯一私人主档、购买/冲煮历史和外部案例中读取器材名称，同时保留来源；把当前有效简称解析到唯一 `canonical_id`；历史记录原始标签只在读取时临时解析，不写回主档或生成第 2 个候选；
4. **保持真实差异**：品牌或系列相同不能合并不同尺寸、材质、代际、联名、底部组件、滤纸产品线/SKU、尺寸或原生形态；缺失关键区分字段时保持 `unresolved`；
5. **声明来源角色**：为每条器材事实标注 `owned_current / session_available / borrowed_this_brew / historical_use / purchase_record / practice_case_equipment / competition_case_equipment / research_only`；
6. **构建双池**：候选池只接收前 3 类；其余进入 `evidence_only_equipment`，可以支持身份、结构、方法或迁移判断，但不能证明当前可用；商品图片和产品资料默认属于证据池；
7. **建立接口与系统身份卡**：先为每只滤杯列出全部已核实接口，每个接口写形状、标称尺寸/型号、成形方式、必要工具/组件和适用底座；再把当前具体滤纸产品映射到接口，建立滤杯主体、当前组件和精确滤纸组成的系统，分别记录主体几何、有效粉床几何、出口拓扑、滤纸原生形态、折法/贴合和旁路状态；
8. **去重并检查**：一个 `canonical_id` 在候选池只能出现 1 次。外部案例与私人库存指向同一实体时，分别保存外部证据和可用性证据，不复制实体；制造商性能主张、配方、第三方观察、个人使用结果和纠错历史不得作为客观缓存。

身份冲突以当前消息的最新明确条件/纠正为最高优先级，其次是会话已确认状态和 `private-coffee-profile.md` 的当前规范实体。购买记录、历史标签、助理猜测和公开同名型号不能覆盖这些信息。公开研究从规范实体及其 `search_seed` 开始；缓存已稳定核实的身份字段不重复搜索，搜索结果若提出新冲突，只能标记并核对，不能静默改写个人实体。只有用户明确要求更新时才写回主档，并直接替换当前值，不保存历史误称或纠错记录。

候选池建立后执行不变量检查：

- 每个候选都有规范精确身份、可用性角色和依据来源；
- 每个滤杯的多个已核实滤纸接口均被保留；兼容判断使用形状、尺寸/型号、成形方式和工具，而不是品牌；
- 每个进入配方的器材—滤纸组合都有完整系统身份卡，组件与滤纸字段来自当前精确对象；
- 没有历史记录原始标签、失效简称或被纠正对象作为独立候选；
- 没有仅因比赛、文章、制造商页面、购买记录或历史使用而进入候选的器材；
- 同品牌不同型号保持独立，历史配方的器材标签已解析到当时正确实体；
- 精确型号已知时没有退回品牌或家族资料，也没有从相邻产品线继承流速、阻力与兼容性；
- 同一接口下的不同滤纸产品没有被视为相同阻力或相同配方；
- 最终输出可以使用用户简称辅助识别，但必须同时给规范精确名称，避免重新制造歧义。

## 先选择路线，再选择参数

对每次已有结果先回答七个问题：

1. 当前杯在专业质量上是否成立，主要缺陷或上限在哪里；
2. 当前滤杯/滤纸的床形、旁路、阻力和热结构是否匹配咖啡与目标；
3. 继续调整当前架构还能获得多大收益，需要消耗多少杯；
4. 用户已有器材中是否存在更直接的实现路径；
5. 当前用户对新器材、新架构、风险和有限豆量的策略是什么；
6. 当前正面记录只是一次成功，还是已经显示稳定区间；其中哪些因素值得保留，哪些只是同一杯同时出现；
7. 四条路线在专业质量、目标匹配、表达覆盖、信息与体验增量、执行风险和咖啡消耗上的总体价值如何。

据此选择：

- `精修当前系统`：现有架构匹配度高，且有一个清楚问题可以用少量联动修复；
- `同器具新架构`：保留滤杯/滤纸，但重新设计比例、热路径、水位与注水结构；
- `更换器材系统`：另一滤杯/滤纸能更直接地实现所需床深、流动、旁路、热或扰动目标；
- `双路线探索`：用两个方向明显不同的完整方案比较，例如快流浅床与浸泡混合，而不是在同一思路上做近邻参数差。

当前系统的历史投入不增加其优先级，正面评价也不授予原系统默认优先权。咖啡量、器材范围和风险只通过当前请求或私人档案中的用户策略参与优化；没有个人策略时采用平衡判断。当前杯接近或达到目标只降低修复缺陷的必要性，下一杯仍选择总体预期价值最高的完整方案。

### 正面结果进入优化

先把正面记录转化为以下状态，再参与路线比较：

1. **质量结论**：哪些专业维度已经成立，哪些只是用户喜欢，哪些仍有表达空间；
2. **基线等级**：单次成功记为 `observed_success`，相近条件下多次成功记为 `repeated_success`，在不同操作波动下仍稳定成立时记为 `validated_range`；
3. **成功因素**：记录被当前证据支持的器材适配、浓度区间、热路径或流动特征，不把同杯全部参数都视为必要条件；
4. **剩余机会**：明确专业质量、目标杯型或对象表达还有哪些真实优化空间；
5. **个人策略**：读取用户对探索、有限豆量、风险和体验覆盖的明确规则；缺失时保持平衡。

对 `精修当前系统 / 同器具新架构 / 更换器材系统 / 双路线探索` 分别写定性路线台账：

| 路线 | 专业质量 | 目标匹配 | 表达覆盖 | 信息与体验增量 | 执行风险 | 咖啡消耗 | 总体预期价值 |
|---|---|---|---|---|---|---|---|
| 精修当前系统 |  |  |  |  |  |  |  |
| 同器具新架构 |  |  |  |  |  |  |  |
| 更换器材系统 |  |  |  |  |  |  |  |

技术上完整且用户满意的杯子没有需要虚构的缺陷。精修、同器具重构、换器材和并行方案都必须通过同一张总体价值台账竞争；若最终继续原系统，路线说明必须指出它相对新架构的新增价值，而不是仅引用上一杯评价正面。局部校正也应处理形成结果的一组耦合变量，避免把“谨慎”简化成每次只动 `1–2` 个数值。

## 器材与粉量共同求解

器材选择从完整候选池开始，不从 agent 熟悉的少数型号开始。先确认当前可用的精确型号、尺寸、材质、版本、滤纸兼容和库存状态，再按本轮有意义的结构与操作能力分组。功能近似的器材可以合并进入同一组，但所选器材和最强替代必须回到精确型号。

### 资料可见度偏差校正门

对候选滤杯使用两个相互独立的判断轴：

1. **当前适配度**：当前粉量与有效床形、滤纸接口与阻力、底部限制/旁路、流动和热需求、咖啡状态、目标杯型、磨豆机/水、操作条件与既有对象结果之间的匹配；
2. **证据置信度**：身份和结构事实的完整度、是否有直接测试或相近案例、版本风险及未解决缺口。

来源数量、搜索排序、品牌知名度、上市时间、比赛出场率和公开配方数量不进入当前适配度。多个网页重复同一厂商文案或同一著名配方，也不构成独立重复证据。证据置信度只用于说明判断有多稳，并按用户本轮风险策略进入执行风险；不得把高置信度等同于高适配，也不得把资料稀少等同于表现较差。

同一家族的多个材质、尺寸或代际保持独立 `canonical_id`，但共享几何、滤纸接口、配方传统和来源链不能充当多张赞成票。先在功能组内比较差异是否影响当前热、粉量、流动或操作需求；不构成决定因素时合并呈现并只保留最匹配代表进入精确短名单，避免一个知名家族因库存变体较多而挤占候选席位。

为每个进入短名单竞争的功能组完成相同最低研究覆盖：

- 规范身份、尺寸、材质、版本和可用性；
- 滤纸接口、物理容量和当前粉量的相对床深；
- 决定流动、旁路、热和操作方式的结构事实；
- 至少一个可迁移方法/观察，或明确记录公开方法缺失；
- 当前案例中的主要优势、失败模式和最大不确定性。

资料丰富的候选达到以上覆盖后停止累积一般介绍；把检索预算转向资料较少但结构上相关的候选。找不到现成配方时，使用可核实结构、稳定理论、相近器材的分维度迁移和可观察结束条件构造方案，并将缺口保留为待验证推断。

按以下顺序筛选：

1. **建立全集**：只纳入已通过实体解析门、具有 `owned_current / session_available / borrowed_this_brew` 依据的全部器材—滤纸组合；待确认身份与已确认型号分开，外部实践/比赛器材留在证据池。
2. **结构分组**：记录有效床形/面积、底部限制与出口、旁路、纸型与阻力、热容量、阀门/分水、浸泡/渗滤能力及操作需求。
3. **适配筛选**：使用当前粉量或可行粉量范围、目标饮料量、滤纸库存、容量和用户条件排除明显不适配组合。
4. **对象排序**：结合当前咖啡与豆龄、目标杯型、水和磨豆机、既有结果、操作容错、剩余咖啡与探索价值排序。
5. **精确决选**：展开最相关的 2–4 个具体型号，选择首选系统，并保留一个最强替代以说明关键取舍。

短名单使用同一候选矩阵，不给“来源数”或“流行度”设评分列：

| 器材—滤纸组合 | 粉量/床形适配 | 流动与热匹配 | 目标杯型 | 主要失败模式 | 当前适配结论 | 证据置信度 | 关键缺口 |
|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |  |

决选前隐藏品牌、型号、来源数量和比赛履历，仅保留上述结构化描述做一次反事实排序。若知名候选失去名称后无法相对最强替代形成对象级区分，它们保持并列或由更匹配者胜出；不能恢复知名候选的默认优先权。若知名候选仍胜出，记录至少一个当前案例特有的区分优势，以及最强替代在同一维度的具体代价。

检查 `brewer_recommendation_history` 只用于发现模板化惯性，不机械惩罚重复选择。同一知名滤杯在不同咖啡中连续胜出时，逐次比较推荐理由；如果理由都只是“通用、可控、资料多、经典、容易找配方”等一般陈述，清空当前短名单并重新从功能组排序。若每次存在不同且可核实的对象级优势，重复选择可以成立。

完整选择思路不等于逐一写几十段器材介绍。最终回答可用功能分组表交代全部候选池的去向，再对短名单和首选进行对象级分析。一般性的“平底更甜、锥形更明亮”不能承担最终选择依据；解释必须连接当前型号、滤纸、粉量、咖啡状态、水、既有结果和目标。

### 粉量影响传播门

用户在请求中指定下一杯粉量时，将其标为 `specified_by_user`，直接作为确定输入。分析目标是把该粉量传播到全部相关参数，而不是重新判断是否采用其他粉量。只有用户没有指定时，才比较可行范围并将结论标为 `selected`；过去冲煮或外部配方中的粉量标为 `historical_candidate`。

在输出配方前填写 `dose_propagation`：

1. `brewer_bed_fit`：当前粉量在候选滤杯/滤纸中的有效面积、相对床深、底部限制、旁路和膨胀空间；
2. `water_beverage_strength`：粉水比、总水量、预计持水量、目标饮料量、浓度与服务体量；
3. `hydraulics_time`：床层阻力、液柱/水位、流量、排液曲线、预计总时和结束条件；
4. `grind_uniformity`：研磨如何与床深和流动匹配，以及细粉迁移、堵塞、通道和均匀性风险；
5. `wetting_pours_agitation`：初始润湿水量、每段水量、段数、流量、动量、落点、水位和扰动；
6. `thermal_path`：粉水热容量、器材热状态、预热、脉冲大小、阶段间隔和时长；
7. `operational_resolution`：称量、磨豆残留、注水流量和动作误差在当前粉量下的相对影响；
8. `uncertainty`：缺少内部尺寸、堆积密度、粒径或实测流速时，哪些判断只能使用相对或条件化表达。

预计总时必须由当前粉量、滤杯/滤纸、研磨、总水量、流量、水位和阶段结构共同推导。粉量增加通常同时改变床深、阻力和总水量，粉量减少则可能放大旁路、热损失和操作误差；这些只是待结合具体器材验证的方向，不可写成脱离条件的固定规律。

初选器材后至少反查 1 次 `dose_propagation`，再锁定研磨、注水和总时。完整回答必须显示粉量对滤杯选择、注水/研磨/水位结构和预计时间的实际影响；只登记粉量数值、来源或“适配”结论不能通过完整性检查。

### 逐段注水—同步排液状态门

预计总时是整条注水、同步排液与水位演化路径的结果。`最后注水结束 + 末段排液` 只是事后分解总时的恒等关系，不能承担预测模型；如果此前各段已经同步排出多少液体、下一段从什么水位开始没有传播，末段剩余量本身就是错误的。每个完整方案内部填写 `recipe.time_budget`，并依次完成以下过程。

#### 1. 锁定系统与事件

先完成 `brew_system_identity_card`，再声明 `timer_start_event` 与 `brew_end_event`。默认从第 1 次注水开始计时；结束事件使用床面失水、目标滴速、截流或移杯等物理事件。滤杯主体、当前组件、滤纸产品线/SKU、原生形态、折法/贴合与旁路状态没有锁定时，时间模型保持条件分支。

#### 2. 建立连续状态

内部跟踪以下量的方向与合理区间：累计注水、咖啡和滤纸吸持、已经流出的饮料、旁路流出、系统内可排液体、水位/液柱、床层膨胀与排气、滤纸湿态、温度、细粉迁移和当前出流能力。以质量守恒检查：`累计注水 = 已流出饮料 + 旁路 + 咖啡/滤纸吸持 + 系统内剩余液体`。没有传感数据时不填伪精确毫升或逐秒曲线，但每一段都要给出相对关系和区间。

#### 3. 逐段传播

对初始润湿和每一段主注水逐行填写：

1. `start_trigger / start_time`：这一段由固定时刻、水位下降、床面显露、目标滴速或其他条件触发；
2. `start_liquid_state`：开始时粉床上方及床内可排液体的相对存量、水位和饱和状态；
3. `pour_mass / input_flow / pour_end_time`：段量、实际平均注水流量与注水持续时间必须算术一致；
4. `concurrent_outflow_relation`：从水到达粉床和滤纸后，排液与注水同步发生。判断当前出流显著低于、接近或高于注水流量，以及这使水位上升、趋稳还是下降；
5. `end_liquid_state`：注水结束时已经排出的部分、系统内剩余液体和水位状态；
6. `interstage_drainage / next_stage_state`：段间继续排液、降温、排气与细粉迁移怎样改变下一段起点。

下一段按固定时刻开始时，起始状态是前一段传播到该时刻的结果；下一段按水位或床面条件开始时，达到该状态所需时间本身由排液过程决定。不能先独立写好全部开始时刻，再在末尾补一个总排液时间。

#### 4. 判断动态出流

出流能力不是滤纸的一项固定秒数。每一阶段同时考虑：精确滤纸的湿态渗透与贴合、滤杯出口和旁路、当前粉量/床深、研磨与细粉、液柱、水温与黏度、气体释放、扰动造成的细粉迁移和此前水位历史。高水位可能通过液柱提高瞬时出流，也可能伴随细粉迁移而降低后续渗透；快速滤纸允许更大的潜在出流，但实际出流仍可能被粉床或出口限制。

当 `input_flow > current_outflow` 时，系统内液体累积且下一段可能从较高水位开始；两者接近时水位可近似稳定；当 `input_flow < current_outflow` 时，边注边降水位是可能的。以上关系要与具体段量、流量、床深和器材—滤纸系统共同判断。

#### 5. 形成结束时间窗口

最后一段继续使用同样的同步排液传播。注水结束时的剩余液体与水位来自此前所有阶段，而不是由总水量或通用末段秒数反推；随后估计达到 `brew_end_event` 的剩余过程。区间上下界分别给出哪些组合状态形成更快或更慢路径，并检查每个边界与逐段水位、注水时刻和结束事件相容。

时间轴推荐使用下表：

| 阶段 | 启动条件/时刻 | 注水量与流量 | 注水中排液关系 | 注水结束状态 | 段间排液与下一段起点 |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

#### 6. 锚点与证据边界

数值锚点只使用当前咖啡、当前样品的实际记录，并优先使用同时记录各段起止、水位或流动状态与结束事件的数据。当前咖啡只有总时而没有阶段信息时，它只能约束整体现象，不能分配各段排液；滤杯、滤纸、粉量、研磨、豆龄或时间轴变化时重新传播全程。

其他咖啡的个人冲煮记录不用于校准当前咖啡的数值时间。公开实践案例可以支持器材结构、操作方法、排液方向和失败模式，但其总时不直接迁移到当前对象。没有当前对象锚点时，从精确器材—滤纸研究、稳定机制、当前粉量和完整注水结构形成条件化窗口与可观察结束条件。

预计时间是配方的一部分，也是过程预测。实际执行时记录各段真实起止、每段开始/结束水位、最后注水结束和实际结束；下一轮用这些当前对象数据更新阶段状态判断，而不是只用一个总时给整套系统加固定修正。

## 初次冲煮

### 1. 找出主导因素

从以下各选出真正影响当前方案的项目：

- 约束：豆龄、可疑烘焙状态、剂量/床深、滤纸阻力、磨豆机细粉、水碱度、用户操作限制；
- 机会：清晰产区信息、烘焙商建议、可迁移同生豆经验、稳定器材和可测水；
- 不确定性：处理标签宽泛、烘焙变化、滤纸版本、产季或样品储存史。

### 2. 选择配方结构

共同设计：

- 粉量、水量、目标饮料量和粉水比；
- 研磨位置及可观察替代定义；
- 水温和热管理；
- 闷蒸水量、时间、覆盖与扰动；
- 每段注水的起止重量、流量、间隔、水位和高度；
- 床层扰动、旁路和结束条件。

设计前先载入已确认的个人默认值。默认值不是无须解释的模板，但具有参数连续性的优先权；当前证据足以支持不同选择时，明确说明为何覆盖。外部烘焙商、比赛或器材配方中的常见时长不能静默替代个人默认。

若当前方法采用独立闷蒸，把它作为注水结构中的一个步骤共同设计，列明水量、时间、覆盖动作和计时起点。沿用已确认默认值且该步骤不是当前问题核心时，在完整配方中写清操作即可；偏离默认值、采用特殊动作、明显影响当前诊断，或用户专门询问时，再解释其对象依据以及与主注水、热状态和流动的联动。

### 3. 做系统预测

逐项说明方案如何共同影响：

- 粉床润湿和气体释放；
- 驱动力、阻力与流速曲线；
- 热状态；
- 平均萃取和局部均匀性；
- 饮用浓度；
- 入口—中段—尾段—余韵。

### 4. 暴露假设

列出 2–4 个最关键假设。为每个假设写明支持证据、反证和下一杯观察。

## 已有冲煮

### 1. 先描述状态

分别判断：

- 饮用浓度；
- 平均萃取程度；
- 萃取均匀性；
- 粉床流动；
- 热管理；
- 水的缓冲/离子作用；
- 烘焙状态；
- 生豆或处理限制；
- 与目标风格的距离。

若缺少 TDS/EY，以“较可能、无法确认”表述，并用过程/感官模式补充。

### 2. 建立候选机制

每个候选机制写成可证伪形式：

```markdown
#### 机制 A：<名称>
- 能解释：
- 不能解释：
- 需要同时成立：
- 与机制 B 的区分观察：
- 当前权重：高 / 中 / 低
```

保留 2–4 个候选。优先选择能解释最多独立证据、假设最少且与对象事实相符的机制。

### 3. 选择调整幅度

- `局部校正`：主结构适配且问题集中，修改一组必要的耦合变量；
- `同器具重构`：器具适配而原配方结构失配，重新设计全套参数；
- `换器材重构`：现有器具架构限制明显，从可用器材中选择更匹配组合；
- `并行探索`：两种架构各自能回答不同杯型方向，给两套完整方案供同日或连续比较。

修改范围由预期收益、器材机会与机制需要共同决定。单变量隔离用于有实际决策价值的因果区分；它不是连续冲煮的默认形式。多项参数共同构成新系统时，逐项说明作用分工、协同关系与预期过程。

已有结果为正面时，先完成“正面结果进入优化”台账。下一杯仍以总体预期价值最高的完整方案为目标；稳定性、信息、体验覆盖和风险只作为优化维度参与，不单独驱动复制或实验。

### 4. 输出完整下一轮

即使多数参数保持，也完整列出，使用 `保持`、`修改`、`重构` 标签。用户无需回看上一轮即可执行。

## 参数协同检查

交付前逐项检查：

- 研磨变化是否同步预测阻力、细粉、时长和均匀性；
- 温度变化是否同步预测黏度、流量、热损失和萃取；
- 指定粉量是否已经传播到床深/器材适配、总水与饮料量、水力/总时、研磨/均匀性、润湿/注水/扰动、热和操作分辨率；
- 段数/流量/水位变化是否同步考虑动量、液柱、热容量和接触；
- 扰动变化是否同步考虑润湿、细粉迁移、堵塞和通道；
- 换滤纸/滤杯是否先重新匹配形状、尺寸/型号、成形方式与工具，再校准有效面积、旁路和热状态；
- 水变化是否区分碱度、离子、感知和设备；
- 旁路是否只改变最终浓度，还是同时改变服务温度和感知。
- 当前滤杯是否因惯性保留；完整候选池是否已经按功能分组进入筛选，短名单、首选与最强替代是否清楚；
- 当前适配度和证据置信度是否分开；是否把来源数量、品牌知名度、比赛履历或现成配方数量错误写成适配优势；
- 同一家族多个版本是否保持身份独立但没有被当作多票；只有当前相关差异才允许多个家族成员同时占据短名单；
- 资料稀少的候选是否获得相同最低研究覆盖；“未找到”是否被错误当成不适配或失败证据；
- 决选是否执行去品牌反事实检查；反复推荐同一知名滤杯时是否存在每杯特有的区分依据；
- 正面记录是否作为证据进入整体优化；是否把“已经好喝”误写成继续精修、复制原配方或只动少量参数的充分理由；
- 每条历史记录是否绑定唯一 `case_id + brew_id`；是否把整杯结果、用户解释和 Skill 因果推断分开；跨对象结论是否具有迁移桥；
- 用户指出的实质方案问题是否建立 `correction`，让受影响决定沿依赖关系失效；未改变参数是否经过重新确认；
- 当前有效简称是否已解析到唯一 `canonical_id`，候选池是否已经去重；每项是否具有当前可用性来源；历史记录原始标签是否只作临时解析；
- 是否只读取 `private-coffee-profile.md`；客观缓存是否精确匹配型号、版本、组件和滤纸后才复用；商品图片是否被错误当成购买或持有证明；
- 是否只增量研究缓存缺失、冲突、版本敏感和组合级字段，并避免把性能主张、配方或个人观察写入客观缓存；
- 最终器材—滤纸系统是否已分别锁定主体、当前组件、主体几何、有效粉床几何、出口拓扑、选中接口、精确滤纸产品线/SKU、原生形态、折法/贴合与旁路；滤杯的其他已核实接口是否仍保留在对象卡中；
- 比赛、文章、制造商、购买或历史记录中的器材是否只承担其来源角色，没有被误写成当前库存；
- 注水步骤中的时间、水量和动作是否与当前床深、流动、润湿和热路径一致；
- 时间轴每段水量、平均流量与起止时刻是否算术相容；每段是否从注水开始同步考虑排液；
- 每段的段初液体/水位、注水中排液关系、段末状态、段间排液和下一段启动状态是否连续传播；
- 预计结束时间是否来自全部阶段后的剩余液体与结束事件，而不是把总排液集中到最后一段；
- 时间边界是否通过质量守恒与阶段状态检查；其他咖啡的个人记录是否被错误用于当前咖啡的数值校准；
- 滤纸、粉量或注水结构改变后是否重建全部阶段，而不是沿用、线性缩放或使用通用总时；
- 个人默认是否被正确继承；若有覆盖，是否写明依据、代价与恢复条件。

- 咖啡状态/静置；
- 用户指定粉量及其对器材、流动/总时、研磨、注水与热的影响传播；
- 水温；
- 研磨；
- 粉水比；
- 器材路线选择；
- 个人默认值的沿用或覆盖；
- 注水结构、流量和水位，包括采用独立闷蒸时的初始步骤；
- 扰动；
- 主要诊断。

使用 `../evidence-policy.md` 的关键决定模板。

## 输出模式与完整性合约

### Full

以下任务默认使用完整模式：

- 新咖啡的第一次方案；
- 已有结果后的下一杯方案；
- 器材、水、粉量或配方架构迁移；
- 需要给出完整操作的比较或重构；
- 任何改变既有可执行参数的追问。

用户在同一对话中说“也看看这支”“顺便给个方案”时，仍按任务实质使用完整模式。完整模式遵守覆盖合约，不要求固定章节数量。

稳定核心包括：

1. **当前对象研究与分析**：始终作为独立章节，综合产品、烘焙商、生豆、产区/产季、迁移经验、器材与水六维研究，写明直接事实、缺口、迁移等级和配方含义。
2. **判断与路线**：已有结果时完成技术诊断，首杯说明主导因素；区分专业质量与用户目标，并给出精修、同器具重构、换器材重构或并行探索的结论。正面记录还要说明基线等级、可保留的成功因素，以及个人探索与有限豆量策略如何参与整体优化。
3. **完整起始方案或完整下一轮方案**：使用方案摘要表和注水时间轴表给出独立可执行的全部参数。
4. **决策逻辑、依据与预期**：解释参数协同、关键数值来源、证据性质和预期过程/感官结果。
5. **观察重点与后续判断**：规定下一杯需要记录什么，以及结果如何更新机制和路线。

根据案例添加或展开：

- **滤杯与滤纸选择图谱**：多个器材可用、器材选择会影响路线、粉量处于适配边缘、用户追问选择依据或正在迁移时出现。用功能分组交代完整候选池，再用同一候选矩阵分别呈现适配度、证据置信度与关键缺口，展开精确短名单、首选和最强替代，并记录去品牌反事实结果。
- **粉量影响说明**：内部每次必做。粉量固定且相容时并入判断或配方逻辑；需要选择、改变或显著影响床深、热、流动、注水、杯数与浓度时展开。
- **关键假设与替代解释**：存在会改变路线的不确定性，或已有结果有多个有竞争力的机制时展开。候选数量由决策需要决定，不机械凑足。
- **证据性质与分歧**：来源冲突、迁移边界或证据较弱时独立展开；简单案例可将标签和来源贴近相应决定。
- **第 2 条探索路线**：能形成实质不同的高价值杯型且咖啡量允许时出现，并提供同等完整的 2 张配方表。

“当前对象研究与分析”保持为第 1 个独立章节；其余标题顺序可围绕案例重心调整，技术判断与路线、决策逻辑与证据也可以合并。模块化只改变组织，不降低对象研究、器材与粉量考虑、执行参数、关键依据和后续观察的覆盖。

### Delta

只有在用户询问某个参数为什么这样设定、要求补充来源、解释机制或改变表达格式，且核对后原决定仍然成立、也没有请求新方案时使用。围绕问题补齐对象依据、机制、联动和原方案影响。若发现原参数没有依据、对象身份/适配错误或遗漏系统联动，建立纠错事件，明确失效范围并转为完整模式重新设计方案。

### Concise

用户明确要求简短回答时压缩重复背景、来源展开和机制文字。仍保留独立对象研究章节、完整配方、路线选择、关键决定依据和观察重点，保证用户无需追问基本操作和主要理由。

## 决策覆盖下限

完整模式交付前检查：

| 决策组 | 至少解释 |
|---|---|
| 对象研究 | 六维研究发现、直接事实、重要缺口、迁移边界及对方案的含义 |
| 器材与滤纸 | 完整候选池的功能分组、精确短名单、首选和最强替代；为什么当前组合匹配当前对象 |

| 研磨 | 用户刻度、相对描述、阻力/流速与均匀性预期 |
| 温度与热 | 壶设定、器材热状态、阶段温度及目标 |
| 初始润湿/闷蒸 | 水量、时间、动作、默认值来源及与主注水的衔接 |
| 主注水与扰动 | 每段重量、流量、液位、高度、落点和扰动分工 |

每个关键数值或参数组标记来源类别：

- `个人默认`；
- `当前对象已经验证的成功因素`；

- `可迁移实践`；
- `当前待验证推断`。

精确数字没有直接对象证据时，明确它是用于启动与验证的中心值。沿用默认值也说明它在当前方案中承担的作用；覆盖默认值时写明依据、收益、代价和恢复条件。

## 数值表达

- 给可直接执行的中心值，并在操作/器材误差有意义时给范围。
- 所有数量、顺序、时间、日期、版本、比例、范围和测量值使用阿拉伯数字；正文、表格和标题编号采用同一规则。
- 粉量、水量、流量、比例、温度和时间优先写为 `15 g`、`240 g`、`5 g/s`、`1:16`、`94°C`、`0:30`、`2:10–2:30`。
- 日期写为 `2026-07-29`，百分比写为 `1.35%`，器材版本和型号保留官方阿拉伯数字形式。
- 研磨同时使用用户设备刻度与可观察校准；不伪造跨磨豆机通用刻度。
- 注水写明累计重量、段内水量、时间或流量、水位和动作；采用独立闷蒸时把它作为第一步列入同一时间轴。
- 时间轴逐行写注水中的同步排液、段末状态和下一段起点；末行写达到最终结束事件的过程，总时行说明快慢边界来自哪些阶段状态。
- 对偏离用户默认值、采用特殊结构或承担主要诊断作用的参数，说明当前依据、联动关系和下一轮调整条件。
- 对沿用的个人默认值和决定结果的关键常规参数，简要说明当前作用，避免出现只有数字而没有选择依据的配方。
- 结束条件优先结合重量/流速/床层状态，避免只给总时间；除明确截流方案外，不为追赶预计时间改变动作。
- 置信度与来源分开写；精确数值不代表高置信度。
