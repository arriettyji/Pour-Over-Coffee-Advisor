# 运行时对象研究流程

## 启动条件

只要请求指向具体咖啡或烘焙商，就对当前产品、烘焙商、生豆生产、产区/产季和可迁移经验进行实时公开研究。器材、滤纸、磨豆机/刀盘与水先检查唯一私人主档的客观缓存；精确匹配的稳定身份字段可直接复用，其余缺失、冲突、版本敏感和组合级字段再增量研究。产品页完整不构成停止条件；各维度提供不同证据，采用并列研究。

若用户只需要解释一般概念，读取稳定理论即可。若用户要求立即给方案而公开资料有限，先交付带条件的方案，同时标注哪些字段会改变方向。

## 输入标准化

先将用户文字和图片整理为六组：

1. 咖啡与当前样品状态；
2. 烘焙商与烘焙背景；
3. 器材与用水；
4. 可控冲煮参数；
5. 过程与感官结果；
6. 当前目标。

保留三种状态：

- `已确认`：用户明确提供或来源可核实；
- `暂定`：识别结果较可信但有同名/版本风险；
- `缺失`：会影响判断且目前没有。

### 唯一私人主档与客观缓存门

当前任务需要使用既有库存、器材简称、滤纸、默认值或历史时，只读取 `private-coffee-profile.md`，不得查找、合并或维护其他持久私人登记。优先级为：当前消息的最新明确条件/纠正 > 当前会话已确认状态 > 唯一主档的当前有效字段 > 通用理论与实践起点。

主档中的滤杯缓存只在品牌、完整型号、尺寸、材质、版本/联名和当前组件与本轮对象完全匹配时复用；滤纸缓存只在完整产品线/SKU、形状、标称尺寸/型号和材质完全匹配时复用，且来源 URL 与核实日期可追溯。可缓存字段包括身份、尺寸、材质、主体几何、出口/阀门，以及按 `形状 + 标称尺寸/型号 + 成形方式 + 必要工具/组件` 定义的全部滤纸接口；品牌不作为接口条件。不得从缓存读取固定流速、时间补偿、配方、性能排名、感官主张、个人观察或单杯结论。

把外部对象证据和个人可用性证据分别解析。产品图片、商品页、文章、比赛资料或厂商兼容表可以支持型号、形态、材料声明与外部用法；除非图片本身是用户明确确认的购买凭证且当前状态仍有效，否则不能建立个人购买或库存。购买记录只支持 `purchase_record`，用户最新明确持有、当前主档或本轮可用陈述才支持候选池角色。

### 器材身份解析前置门

公开搜索和器材比较必须从规范实体而不是原始简称开始。先按 `../personal-profile.md` 生成：

```yaml
equipment_resolution:
  private_profile_source: private-coffee-profile.md | none
  objective_cache_hits: []
  objective_cache_misses: []
  objective_cache_conflicts: []
  raw_mentions: []
  canonical_entities: []
  alias_resolution: []
  unresolved_mentions: []
  availability_ledger: []
  candidate_pool: []
  evidence_only_equipment: []
  filter_interface_registry: []
  brewer_compatible_interfaces: []
  owned_filter_interface_mapping: []
  brew_system_identity_cards: []
```

私人主档只保存当前规范名称和仍在使用的简称；历史误称、误记材质、被纠正版本和失效别名不写入主档。历史冲煮记录保留的原始标签只在读取时临时解析到 `canonical_id`，不能继续作为独立搜索对象或候选项。同品牌/系列的不同尺寸、材质、代际和底部组件保持独立。搜索可以发现私人记录与公开规格存在冲突，但不能静默覆盖用户最新确认；若冲突会改变方案，显示冲突并集中核对。

每只滤杯先保存 `brewer_compatible_interfaces`，每项至少记录滤纸形状、标称尺寸/型号、成形方式、必要工具/组件、适用底座、兼容依据和确认状态；同一滤杯的多个接口并列保留。每个当前具体滤纸再以完整品牌/产品线/SKU、材质、形状、标称尺寸/型号映射到一个接口，品牌本身不证明兼容。

每个 `brew_system_identity_card` 至少记录：滤杯主体精确身份，尺寸/材质/版本，当前底座/阀门/转换件，主体几何，有效粉床几何，出口与旁路拓扑，选中的滤纸接口，滤纸完整品牌/产品线/SKU/尺寸，滤纸原生形态，实际折法/贴合/预湿，滤杯—滤纸兼容依据，以及各字段的确认状态。主体几何、滤纸几何和组合有效床形分别保存；滤杯能兼容某种纸不表示二者属于同一几何，也不表示同接口下的不同产品具有相同湿态阻力。模块化滤杯按当前组件建立系统卡，同一主体的不同组件不共享出口与流动字段。

精确对象已知时，后续检索保持在该对象层级。品牌、系列、相邻尺寸、旧版/新版或另一产品线的资料只能建立迁移项，必须写共享条件与差异；它们不能补写当前对象的流速、阻力、兼容、容量或感官表现。精确对象资料有限时，保留精确身份并降低性能置信度，不把身份退化成资料较多的近邻型号。

可用性和研究价值是两个不同判断。候选池只接受 `owned_current`、`session_available` 和 `borrowed_this_brew`；冲煮历史、购买记录、制造商页面、器材测试、实践文章和比赛方案中的器材进入 `evidence_only_equipment`。某外部器材另有当前可用性证据时，才以相同规范实体进入候选池，且两条来源角色分别保留。

## 并列研究维度

### A. 当前产品

确认：

- 产品全名、别名、语言变体；
- 生产者、庄园、地块、合作社、处理站；
- 品种、处理、发酵、干燥、海拔；
- 采收季、生豆到仓/上市、烘焙日期；
- 烘焙商产品页、包装描述、养豆和冲煮建议。

产品消失时查找烘焙商档案、进口商、缓存页面、经销商和同批公开内容，并明确来源层级。

### B. 烘焙商

独立研究：

- 长期烘焙理念与产品线差异；
- 常用机器、批量、颜色/失重等公开指标；
- 养豆与冲煮建议；
- 近一年设备、团队、生产地点或风格变化；
- 与当前咖啡相关的其他产品。

把“长期风格”和“当前批次事实”分开。近期变化可降低历史经验的迁移权重。

### C. 生豆生产背景

沿生产者—庄园—地块—处理站—品种—处理的交叉关系研究：

- 农艺与海拔/微气候；
- 采收与成熟分选；
- 发酵容器、氧条件、时长、温度、pH、菌种；
- 干燥方式、层厚、翻动、终点；
- 仓储、出口商、进口商与物流。

同一生豆被其他烘焙商使用时，分别记录原料共同点和烘焙差异。

### D. 产区与当前产季

研究微产区和较大产区的：

- 当季温度、降雨、异常天气；
- 开花、成熟和采收节奏；
- 发酵/干燥环境；
- 仓储、港口与物流；
- 相对历史年份的变化。

产季资料影响历史经验权重，不直接生成风味或参数。

### E. 可迁移经验

按共享条件搜索：

- 同烘焙商/产品线/机器；
- 同生产者/庄园/地块；
- 同生豆跨烘焙商；
- 同品种、处理体系和产季；
- 相近生豆状态、烘焙状态和器材组合。

每项迁移使用 `../evidence-policy.md` 的四级体系，记录共享条件、可支持判断、关键差异和验证方法。

### F. 器材与水

先复用精确匹配的客观缓存，再确认仍缺失或本轮关键的准确身份与组合信息：

- 滤杯品牌、型号、尺寸、材质、版本和当前底座/阀门/转换件；
- 滤杯支持的全部滤纸接口：形状、标称尺寸/型号、成形方式、必要工具/组件和适用底座；
- 滤纸品牌、完整产品线/SKU、尺寸/型号、原生形态、材质、产地/批次型、折法、贴合和预湿，并映射到相应接口；
- 磨豆机、刀盘、版本、校零/刻度体系；
- 水源、处理方式、Ca、Mg、碱度、pH、电导率及其他重要离子；
- 水壶、温控方式、海拔和室温。

客观缓存命中后不重复检索已经稳定核实的型号、材质、尺寸、主体几何、出口/阀门和接口。兼容筛选先匹配形状、尺寸/型号、成形方式和工具，再读取具体滤纸产品的材质与阻力；不能按品牌列候选，也不能因当前只拥有一种纸而删除滤杯的其他已核实接口。研究仍聚焦实际滤纸贴合/折法/旁路、有效粉床几何、当前组件、当前粉量容量、湿态阻力、批次差异、热路径、PSD 与组合流动。制造商规格优先用于型号结构与兼容声明；独立方法完整的测试用于组合性能。把厂商对“快、平衡、洁净”等性能描述标为厂商主张，除非有方法完整的独立数据支持，不把它转换成固定流速或秒数。制造商、比赛和测试来源只能回答“这个对象是什么或如何被使用”，不能回答“用户是否拥有它”；最终器材候选仍以可用性台账为准。

预计水力与时间时，精确检索当前滤纸产品线/SKU、尺寸、批次型、贴合/折法及当前滤杯组件组合。优先寻找同时报告粉量、研磨、每段注水起止/流量、段间水位条件和结束事件的完整记录；只有总时的案例只能作为低分辨率过程背景。公开案例用于识别可能的流动关系和失败模式，不能把另一咖啡的总时直接迁移到当前对象。当前咖啡已有实际记录时，保留其逐段时间、当时器材/滤纸、豆龄和水位差异；没有当前对象记录时，从精确对象事实与逐段状态传播建立条件化窗口。

### 候选器材研究覆盖

多个滤杯参与选择时，先从客观缓存为全部精确候选预填身份卡，再按结构与本轮任务建立候选组；不需要为每次配方重新搜索整个库存的基本规格。随后为每个有竞争力的组补齐相同最低决策覆盖：当前组件和精确滤纸组成的完整系统卡、实际贴合/折法、当前粉量与容量、组合级流动/热结构、一个可迁移方法或明确缺口、主要失败模式。系统卡未完成时保持条件分支；关键缺口会改变配方方向时集中询问。不要先搜索最熟悉的器材并让它的资料量决定短名单。

公开资料丰富的候选达到最低覆盖和当前决策需要后停止继续累积一般配方；把检索投入到资料较少但结构相关的候选。对后者生成原始语言、设计者、制造商、联名方、旧型号和纸型组合词；仍无资料时，记录已查维度，并用已核实结构、稳定理论和相近对象的分维度迁移继续比较。

每个候选分别输出：

- `case_fit`：对当前咖啡、粉量、滤纸、水、目标和操作条件的适配判断；
- `evidence_confidence`：身份/结构事实、直接测试、迁移案例与版本风险形成的置信度；
- `missing_information`：尚未确认且可能改变方向的信息；
- `visibility_sources`：资料链条的独立性，不把转载数量当作重复证据。

研究停止规则按候选的“决策相关字段是否足够”判断，不按全网资料数量判断。缺少公开配方不能排除候选；只有已确认的物理不适配、耗材不可用或当前操作约束才支持排除。

## 搜索表达生成

为对象生成：

- 中文、英文、原始语言；
- 常见译名、旧名称、别名、拼写变体；
- 产品年/季、批次、品种代码；
- 制造商型号、旧版/新版、尺寸；
- 生产者、出口商、进口商、烘焙师和相关人物。

## 来源图谱

从每个重要来源继续提取：

- 人物；
- 产品与同批生豆；
- 庄园、处理站、出口商/进口商；
- 文章、论文、视频、赛事；
- 被引用资料和时间线。

第一方用于身份与声明；同行评议/标准用于机制；方法完整的实践来源用于观察与方案案例。

每条器材来源同时标注 `identity_fact / availability_evidence / historical_clue / practice_case / competition_case / research_only`。同一页面可以支持型号结构和方法事实，但不能因此获得库存证明角色。

## 进入最终回答

所有完整配方回答都设置独立的“当前对象研究与分析”章节。该章节按照当前决定综合六个并列维度，至少呈现：

1. 能够核实的当前对象事实和样品状态；
2. 烘焙商、生豆生产与产季对当前案例真正相关的发现；
3. 共享条件与差异均清楚的可迁移经验；
4. 器材、滤纸、磨豆机/刀盘和水的准确身份与结构含义；
5. 重要资料缺口、版本风险和迁移等级；
6. 上述研究怎样改变器材路线、温度、研磨、比例、注水或观察重点。

第一节负责把研究结果转化为对象画像与冲煮含义，证据章节负责分类和追溯来源，两者同时保留。对象资料稀少时，清楚呈现并列维度形成的先验和缺口；对象资料丰富时继续筛选真正影响当前决定的事实。

当回答包含滤杯选择图谱时，使用规范精确名称，并显示每个候选的可用性依据。历史记录中的原始标签不能重复成为候选；实践或比赛案例中的器材若没有独立可用性证据，只能出现在“迁移经验/证据”而不能出现在“用户可用候选”。

## 提问与停止规则

当现有信息足以给出合理方案时直接分析。只有某个缺失字段会明显改变整体结构时，集中提出一个高价值问题，并同时给出条件化初步方案。

对象研究在以下条件下可以进入分析：

- 身份和当前样品状态达到可用置信度；
- 六个并列维度均已检索或记录为何无资料；
- 至少明确一项直接事实、一个理论机制和主要不确定性；
- 迁移经验均写明共享条件与差异；
- 继续搜索的预期信息增益已经较低，或用户需要即时执行。

研究停止不表示所有字段齐全；它表示剩余不确定性已经显式进入方案与验证。
