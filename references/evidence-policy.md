# 证据、来源与迁移政策

## 目的

让每个影响冲煮方案的关键决定都能回答四个问题：

1. 已知什么？
2. 通过什么方法知道？
3. 在当前对象上能迁移到什么程度？
4. 哪一部分是 Skill 的当前推断？

## 四类决策依据

| 类别 | 定义 | 运行时标签 | 允许的作用 |
|---|---|---|---|
| 稳定知识 | 同行评议研究、学术/技术专著、标准、研究报告或方法完整的专业资料 | `[稳定知识]` | 支持机制、测量、变量关系与边界 |
| 实践观点 | 从业者、研究者、烘焙商、器材开发者、赛事与教学资料中的观察、方法或解释 | `[实践观察]`、`[实践解释]` | 提供现实方法、重复观察、争议和可检验假设 |
| 当前对象事实 | 当前产品、生产者、烘焙商、器材、水与用户样品的可核实资料 | `[对象事实]` | 确认身份、状态和直接约束 |
| 当前分析推断 | Skill 综合上述证据后对当前案例提出的机制与建议 | `[当前推断]` | 连接证据与方案，并规定验证方式 |

实践来源中的观察与解释必须拆开。作者报告“流速变慢”属于观察；作者归因为“细粉迁移”属于解释，后者需要理论或独立证据支持。

## 不同资料承担不同工作

不要用论文实验的单一尺度评价所有参考资料。先判断资料类型，再判断它是否足以完成该类型应承担的工作：

| 实践资料类型 | 首要评价问题 | 可以承担的工作 | 不直接承担的工作 |
|---|---|---|---|
| 完整操作方法 | 对象、器具、粉量、水、步骤和结束条件是否足够完整 | 复现方法、提取配方结构、生成起始方案 | 证明方法在所有对象上最优 |
| 长期实践观察 | 使用范围、次数、版本变化和反例是否交代 | 建立现实先验、容错范围、常见失败模式 | 单独证明普遍机制 |
| 特定咖啡/器具案例 | 对象身份与条件是否完整 | 保留组合经验，按共享维度迁移 | 把对象名称改写成固定规律 |
| 对照测试或作者测量 | 对照、重复、仪器和误差是否适合所问问题 | 支持条件化的过程或性能比较 | 自动升级为稳定理论 |
| 制造商/烘焙商资料 | 版本、结构、兼容和官方方法是否为第一方 | 确认对象事实与设计意图 | 无独立证据时证明性能或感官机制 |
| 比赛方案 | 咖啡、舞台目标、服务温度和完整操作是否可还原 | 提供高约束方法案例与风格设计 | 因名次而证明机制或通用最优 |
| 教学/概念框架 | 术语、决策结构和适用前提是否清楚 | 组织问题、提示变量、生成检验步骤 | 替代原始研究的因果结论 |
| 历史、访谈与行业报道 | 人物、日期、版本和原话是否可核实 | 建立来源图谱、版本史与检索线索 | 直接决定冲煮参数 |

“没有盲测、TDS 或统计”不是完整方法、历史资料或器材说明的固有缺陷。只有当资料被用来回答普遍因果、定量效应或优劣比较时，才检查它是否具有相应的实验支持。反过来，一篇带测量的实践文章也不会因此取代固定理论库；它仍应在自己的对象、设备和方法范围内使用。

## 理论来源准入

理论固定库采用以下来源：

- 同行评议论文及其补充材料；
- 学术专著和学术编著；
- 具有明确作者、方法与引用的技术专著；
- 国际、国家或专业组织发布的标准；
- 研究机构、行业组织或公共机构发布且说明方法的研究报告；
- 具有完整研究对象、对照、测量和限制说明的专业资料。

评估顺序：

1. 优先原始研究和当前有效标准。
2. 学术编著负责综合，关键参数追到原始研究。
3. 系统综述用于判断整体一致性和缺口，仍保留纳入研究的异质性。
4. 技术专著中的同行评议结果、作者测量、计算推导和经验建议分别标注。
5. 通俗专业书用于术语、流程背景和检索表达，不单独承担因果或定量结论。

## 来源评价维度

以下字段按资料类型选用，不要求历史文章虚构实验设计，也不要求一份完整配方提供不相关的统计：

- 身份：作者、机构、日期、题名、版本、DOI/URL；
- 位置：页码、章节、表图、网页小节或时间戳；
- 对象：咖啡、原料、烘焙、器材、水、样本量；
- 资料类型：完整方法、长期观察、特定案例、对照测量、产品资料、比赛、教学框架、历史/访谈；
- 设计：若资料提出实验或定量比较，再记录实验、观察、模型、综述、标准或案例设计；
- 控制：若结论依赖比较，再记录对照、随机、盲法、重复、校准；
- 测量：若资料报告测量，再记录仪器、感官方法、统计和不确定度；
- 结果：作者直接测到或观察到的内容；
- 解释：作者提出的机制；
- 限制：样本、范围、混杂、模型假设和外推风险；
- 决策作用：能支持什么、单独不足以证明什么。

## 来源可见度与独立证据

公开资料数量不是器材适配度，也不自动等于证据强度。知名产品往往产生更多搜索结果、配方转述、比赛曝光和同源转载；这些来源可以提高对象身份、版本、常见操作范围与已报告失败模式的可见度，但不能单独证明它更适合当前咖啡。

评价多个器材时：

1. 分开记录“当前适配度”和“证据置信度”，不设文章数量、搜索排名、品牌知名度或比赛次数加分项；
2. 判断来源是否真正独立：重复厂商文案、复述同一冠军配方、引用同一测试的数据只算一条证据链；
3. 给有竞争力的候选相同最低研究覆盖，资料丰富候选达到决策需要后停止堆叠一般来源；
4. 资料稀少表示不确定性较高，不表示性能较差；继续用结构事实、稳定机制和分维度迁移形成条件化判断；
5. 只有当用户本轮明确重视可靠性且资料缺口确实增加执行失败风险时，较高置信度才通过“执行风险”影响总体价值，仍不能伪装成器材本身更匹配。

同一家族的多个材质、尺寸或代际保持独立对象身份，但共享设计、滤纸、配方与来源不能在比较中重复计票。多个版本只有在当前相关差异足以改变适配判断时才分别进入短名单。

## 对象身份、库存与性能证据分离

同一资料可以证明产品存在，却不能因此证明个人拥有，也不能自动证明性能。运行时分别记录：

1. `identity_fact`：厂商页、包装或清晰产品图片支持品牌、完整产品线/SKU、尺寸、原生形态和版本；
2. `availability_evidence`：用户明确陈述、当前权威库存或本轮可用信息支持个人持有与可用状态；
3. `purchase_record`：订单、购买邮件或收据支持曾购买，不自动等于当前仍有库存；
4. `performance_observation`：方法完整的测试或实践案例支持特定组合下的流动观察；
5. `manufacturer_claim`：厂商对快流、平衡、洁净、兼容或感官的声明，需要与独立观察分开。

商品页图片、比赛图片和用户为研究而上传的产品截图默认只建立 `identity_fact` 或 `research_only`。助理先前写成“购买图”或“用户确认”的标签不能高于用户最新纠正。用户明确说从未拥有某产品时，当前库存、别名映射与候选池立即删除该对象；开放对象研究可以保留产品本身，并记录它与个人库存无关。

精确滤纸产品线/SKU 已知时，以该对象建立证据链。相同品牌的不同产品线、不同尺寸、Wave/锥形/圆片形态和 FAST/平衡等版本分别建对象；近邻产品的流速、阻力、折法和兼容性只能作为带差异的迁移资料。

## 证据强度

- `A`：多项直接研究或高质量系统综述方向一致；或标准化测量关系清楚。
- `B`：至少一项直接同行评议研究或权威技术来源支持，样本/设备/范围有限。
- `C`：间接研究、模型、有限样本、作者原创测量或条件相近的多项实践观察。
- `D`：背景解释、单一案例、待验证机制或用于设计下一杯的弱先验。

强度只在写明的对象与条件内成立。把研究迁移到明显不同的咖啡、设备或范围时，至少降低一档。

## 迁移等级

| 等级 | 定义 | 示例 | 使用方式 |
|---|---|---|---|
| 直接信息 | 当前产品/批次/器材的第一方资料或用户实测 | 当前烘焙日、滤纸型号、实际水报告 | 可直接进入状态表，仍核查版本和样品一致性 |
| 较强先验 | 共享多个关键条件，差异可解释 | 同生豆、同烘焙商、相近日期和同器材 | 可影响起始结构，并写明差异 |
| 较弱先验 | 只共享一个或少数相关条件 | 同品种不同产区；同机器不同烘焙商 | 用于生成候选机制，不独立决定参数 |
| 待验证推断 | 由理论、对象事实和实践观察综合形成 | 推测当前慢流来自细粉迁移 | 必须给支持/反驳观察和下一杯验证 |

每次迁移记录：

1. 原对象与当前对象共享的条件；
2. 可支持的具体判断；
3. 关键差异；
4. 迁移等级；
5. 提升或降低可信度所需的新证据。

## 用户冲煮记录的证据粒度

一条用户冲煮记录首先是一项当前对象观察，其最小证据单元是完整的 `case_id + brew_id + 配置 + 过程 + 感官结果`。它直接支持“这次完整配置出现了这些过程和杯中表现”，并为同一咖啡的下一轮提供对象级历史。

从单杯观察建立进一步结论时使用以下层级：

| 层级 | 可以支持 | 仍需补充 |
|---|---|---|
| 完整配置观察 | 该杯实际参数、过程、感官和用户评价 | 缺失字段、记录误差与样品状态 |
| 同一对象候选机制 | 哪些机制能够共同解释该杯 | 对照结果、独立过程证据或后续反证 |
| 同一对象成功/失败因素 | 多次独立冲煮中稳定共同出现的关系 | 改变边界条件后的稳定性 |
| 跨对象候选先验 | 共享器材、纸、粉量、烘焙或水的某个受限判断 | 共享条件、关键差异、迁移等级和目标验证 |
| 个人稳定默认或偏好 | 用户明确声明，或多对象重复模式经用户确认 | 适用范围、例外和更新时间 |

整杯结果同时由多项耦合条件产生。单杯的苦、涩、甜、清晰、总时或正面评价本身不识别某个滤杯、温度、研磨、闷蒸或注水段的独立效应，也不证明该参数必要、最优或适用于另一咖啡。用户明确说“这杯因为某项而怎样”时，把它保存为用户解释；它在当前案例中具有重要诊断价值，因果强度仍由对照和其他证据决定。

重复粘贴、引用或汇总同一 `brew_id` 只算同一证据单元。建立重复模式时确认记录来自不同冲煮，并比较咖啡、豆龄、器材、纸、水、粉量、研磨、温度、注水、环境和目标。跨对象使用任何单杯记录时，按迁移模板记录它具体支持什么；共享一个标签只能生成候选机制。

## 冲突处理

来源结论不一致时按以下顺序比较：

1. 是否实际回答同一个问题；
2. 咖啡、烘焙、器材、水、目标和温度范围是否相同；
3. 测量的是过程、化学、描述性属性、质量还是喜好；
4. 作者报告的是观察还是解释；
5. 是否控制 TDS、EY、流量、时间等共同变化变量；
6. 样本、重复、盲法、统计和模型假设是否足以支持结论；
7. 哪个结果与当前对象更接近。

保留能够由条件差异解释的分歧。无法解释时并列呈现，并把下一杯设计成区分性测试。

## 关键决定台账

对咖啡状态、静置、粉量及其影响传播、器材架构、水温、研磨、粉水比、闷蒸、注水结构、流量、水位、扰动、时间预算和诊断等决定，使用以下最小记录。粉量由用户指定时，“选择”记录其输入来源，重点记录它如何改变器材/床深、水量/饮料量、水力/总时、研磨、注水/扰动与热；用户指定本身不能替代影响分析。闷蒸决定需要把“润湿与气液置换的稳定机制”“当前豆龄、床深、纸阻与动作事实”“具体秒数的当前推断”分别列出。预计总时还要记录精确器材—滤纸系统、计时起点/结束事件、每段注水中的同步排液关系、段末水位/液体状态、段间排液、下一段启动状态、当前咖啡锚点和质量守恒检查：

```markdown
### 决定：<名称>

- 选择：
- 目标：
- 稳定知识：
- 实践观察：
- 实践解释：
- 当前对象事实：
- 当前分析推断：
- 关键差异与反证：
- 预期过程变化：
- 预期感官变化：
- 下一杯如何验证：
- 置信度：高 / 中 / 低
```

## 引用规则

1. 直接事实尽量引用第一方；机制尽量引用原始研究。
2. 网页使用标题、发布者、日期、URL 和小节；视频/播客增加时间戳。
3. 书籍使用版本、章节和印刷页码；PDF 页码与印刷页码不一致时两者都记。
4. 图片识别出的包装文字标注为用户提供，模糊字段写为待确认。
5. 搜索摘要只能用于定位来源；关键决定引用原文或完整方法资料。
6. 引文服务于决定，默认简洁转述并链接来源。

## 透明度下限

最终建议至少让用户看见：

- 哪些是可核实事实；
- 哪些是较稳定机制；
- 哪些是实践者的观察或解释；
- 哪些是针对当前杯子的推断；
- 当前最大信息缺口；
- 下一杯怎样验证。
