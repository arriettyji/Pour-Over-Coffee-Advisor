# 评测说明

本目录评估 Skill 是否真正执行“固定知识 + 运行时对象研究 + 结构化分析”，而不是只生成看似专业的配方。

- `cases.md`：45 个必测情境及期望行为。
- `rubric.md`：100 分评分量表、硬性门槛与失败等级。

每个案例应在允许联网的环境中运行。评测者保存检索来源、最终回答和关键决定台账；如测试输入声明某资料不可公开获得，Skill 应记录缺口并使用条件化先验，而不是伪造来源。

建议流程：

1. 对每案独立启动，不携带其他案例记忆。
2. 记录 Skill 是否提出问题；只有缺失项会明显改变整体方向时才应集中问一个问题。
3. 用 `rubric.md` 打分。
4. 对下一杯结果型案例追加第二轮输入，检查是否更新机制权重而非重复原建议。
5. 任何来源或参数事实错误都回到原载体核查。
6. 对多咖啡连续对话检查章节覆盖是否稳定，并核对上一对象的临时条件是否留在原作用域。
7. 检查完整配方是否同时具有摘要表和注水时间轴，并确认所有定量信息都使用阿拉伯数字。
8. 对多器材案例检查完整器材池是否先按功能进入筛选，再收敛到精确短名单、首选和最强替代。
9. 检查用户指定的粉量是否在首轮回答中传播到器材/床深、水量/饮料量、水力/总时、研磨、润湿/注水/扰动、热和操作分辨率；后续追问才补做不计为首轮通过。
10. 比较简单首杯与复杂诊断的输出，确认核心覆盖稳定，同时章节数量和解释篇幅能够随任务变化。
11. 对器材别名回归案例检查旧称先归并到唯一规范实体，候选池没有重复项。
12. 对比赛与实践案例检查其中器材只进入证据池；没有当前请求或私人档案的独立可用性证明时，不得进入用户候选池。
13. 对同品牌多版本案例检查尺寸、材质、代际和组件保持独立，并让每个候选显示可用性角色与来源。
14. 对正面冲煮记录检查其作为成功证据参与整体优化，不因“好喝”自动转入精修、复制或只改少量参数。
15. 用“私人档案高度鼓励探索且有限豆量重视体验覆盖”与“另一用户重视单杯可靠性”两种条件检查通用 Skill 是否正确读取个人策略。
16. 对资料密度悬殊的滤杯检查适配度与证据置信度是否分开，资料较少候选是否获得相同最低研究覆盖。
17. 对连续推荐知名滤杯的案例检查去品牌反事实是否成立；不得因文章多、比赛多或容易找配方继续沿用模板化推荐。
18. 对总时间检查每段水量、流量与起止时刻是否算术一致，并检查注水期间的同步排液、段末液体状态、段间排液和下一段起始状态是否逐段传播。
19. 对滤纸、粉量和注水结构同时变化的案例检查是否从第 1 段重建时间路径，而不是沿用、线性缩放、固定加减秒数或只重建末段排液。
20. 对单次历史冲煮检查是否保留完整配置与原对象作用域，是否把整杯观察、用户解释和参数因果分开。
21. 对用户指出配方问题的案例检查是否沿依赖关系重审路线和全部下游参数，并重新输出完整方案。
22. 对唯一 `private-coffee-profile.md` 检查当前消息/会话覆盖、客观缓存精确命中和组合级增量研究，并确认产品页不被当作拥有证据。
23. 对同品牌不同产品线、尺寸或原生形状的滤纸检查是否保持独立身份，别名只映射到唯一规范实体。
24. 对可更换底座或非原生纸形检查滤杯本体、滤纸、有效粉床几何、出口拓扑、贴合和旁路是否分开建模。
25. 对时间数值锚点检查是否只使用当前咖啡与当前样品的记录；其他咖啡的个人记录只能支持结构和方向先验。
